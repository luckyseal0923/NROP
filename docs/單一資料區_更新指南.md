# NROP 單一資料區更新指南

依使用者要求，填報與範例共用同一資料區。畫面移除正式／DEMO 選單與分區提示，填報、管理儀表板、異常紀錄及匯出都讀寫同一份資料。原有範例保留，正式啟用前再清除。

## 現有 Supabase 的操作順序

1. 先備份 NROP 資料，暫停填報，避免更新期間有人修改。
2. 在 Supabase Studio → SQL Editor 新增查詢，將專案 `supabase/UPGRADE_005_007.sql` 整份貼上執行。這份檔案包含護理部、人工審核及資料整併，尚未更新 005／006 的環境也可使用。
3. 成功後執行 `supabase/004_verify_install.sql`：`legacy_partition_records` 應為 0；若原本只有範例，總紀錄及範例來源數都是 7,224。已有人工填報時，總紀錄會更多。
4. 將本次網站變更推送 GitHub，在 Coolify 重新部署。NROP 的兩個公開 Supabase 變數必須設為 Available during build；重新建置後才會帶入網頁。
5. 重新登入，確認沒有資料區選單。選 2026-10-25 查看既有範例，選今天新增填報；管理儀表板與匯出使用同一份紀錄。

已安裝的環境使用 UPGRADE，不重跑 INSTALL。新環境則使用最新 INSTALL，會直接將範例放入唯一資料區。

## 整併保護

- 原有範例搬入共用資料區，保留日期、班別、單位、數字、狀態、版本與更新時間；人工填報也保留。
- 相同日期／班別／單位若已在兩區各有一筆，更新會停止並回滾，不自動選一筆覆蓋。相同單位有兩組期初人數時亦會停止，需要先比對。
- 所有範例與新增紀錄一併查詢、修改及統計，依原角色與單位權限控管；前端不能藉由填報欄位改變來源標記。
- 原範例首班有可追溯的住院基準，可直接修改；新建的空白住院單位仍由管理者設定期初人數。
- 最新網站遇到尚未更新的資料庫，會提示執行 UPGRADE_005_007.sql，不會把尚未整併的資料誤顯示為空白。

## 正式啟用前的清除方式

目前不清除任何資料。資料庫以 `is_sample` 記錄是否由範例匯入；這是來源資訊，不會產生另一個畫面或資料區。修改原範例仍保留來源標記；自行新增的填報則不會被標記為匯入範例。

正式啟用前先執行 `supabase/008_sample_inventory.sql`，盤點範例、自行新增的紀錄及預計保留的住院首班基準。此檔只有查詢。確認保留範圍後再清除範例；如果新增住院紀錄接續範例，須一併核對正式首班的期初人數。帳號、角色及單位設定可保留。

這次不新增會在平常操作時誤刪整批資料的按鈕；清除作業留到使用者決定正式啟用時執行。

## 程式相容性

為沿用既有 RPC 與主鍵，資料庫內部保留 `dataset` 欄位與函式參數，但資料表約束只允許固定值 `live`，所有網站請求皆使用此值。`demo` 參數會被拒絕，不會存在另一個可填寫的資料區。一般使用者不會看到這些內部欄位。

使用者已回報執行更新，本次唯讀 API 檢查確認 dataArea=shared。單一資料區與登入主視覺版本依使用者要求同步 GitHub；網站是否已部署須另外確認。
