## 測試範圍

| 範圍 | 結果 |
| --- | --- |
| 匿名、待審核、停用帳號 | 無法存取填報資料；是否可用由管理者核准，不依賴收取驗證信 |
| 平台使用者 | 僅可讀寫指定單位；不能修改角色或管理帳號 |
| 一般管理者 | 可跨單位填報／統計，不可管理帳號 |
| 系統管理者 | 可核准／停用、指定角色、調整申請開關、查稽核紀錄 |
| 停用後仍持舊身分 | 下一次資料庫讀寫立即拒絕；重新申請不能自行啟用 |
| 共用 Supabase | 既有 Auth 使用者不自動取得 NROP 資格；不修改其他平台範例表 |
| RLS | 無直接 schema／表權限；即使測試中暫時授予 SELECT，仍預設回傳 0 列 |
| 第一班 | 管理者設定期初；無前班／期初時不得正式送出 |
| 人力 | 三位小數；拒絕第四位小數與非整數人次；護理之家 0.1＋0.2＝0.3 |
| 住院分類 | 6A／6B 本科與非本科、12B／ICU-3 一般與負壓合計由 DB 計算；病危不影響住院數 |
| 血液透析 | 門診、住院、重症；重症為必填欄位 |
| 後續班 | 按 N→D→E 重算，更新版本與稽核；負住院數回滾；有後續正式紀錄不得退回前班為暫存 |
| 多人同時修改 | 舊版本拒絕覆蓋，提示重新載入比對 |
| 單一資料區 | 範例與人工填報一起讀寫、統計；資料表只接受固定 live，拒絕舊分區請求；seed 重跑不覆蓋既有紀錄 |
| 舊環境整併 | 7,224 筆範例與人工紀錄保留原數值、版本、更新時間及帳號；更新可重跑，紀錄或期初衝突完整回滾 |
| 範例修改與來源 | 首班採原有住院基準，後續新增可續接；is_sample 由資料庫管理，前端不能偽造 |
| 安裝／初始化 | 安裝重跑不刪除資料；首位管理者腳本只提升指定帳號，已有管理者則拒絕 |
| 護理部／更新 | 29 個申請選項、28 個填報單位；護理部待審核且無自動提權；005／006 更新可重跑，既有成員及全部 DEMO 雜湊保持一致 |
| 六碼英數／不寄驗證信 | 六碼英數可申請與變更密碼，短碼及純英文／純數字被拒絕；Auth 未啟用自動確認時不呼叫 signUp；新帳號進待審核而非進入平台 |
| 瀏覽器表單邏輯 | JSDOM 驗證錯誤密碼不進入平台、無角色選單、角色頁籤、護佐人力合計、資料區選單及分區提示已移除、歷史範例直接修改、帳號姓名安全轉義 |
| 快取與錯誤 | 過期查詢不蓋掉新資料，讀取失敗清空快取並隱藏舊表格；無 localStorage 營運資料寫入 |
